# STS Stock Management (Soil Testing Siam)

ระบบจัดการสต็อกสินค้า — React + Vite + Tailwind + Zustand + Supabase

## ติดตั้ง / รันบนเครื่อง

```bash
npm install
cp .env.example .env   # ใส่ VITE_SUPABASE_URL และ VITE_SUPABASE_ANON_KEY ของโปรเจกต์ Supabase
npm run dev
```

## ระบบสมาชิก: สมัครแล้วต้องรอผู้ดูแลระบบอนุมัติ

ระบบใช้ **Supabase Auth** ในการเข้าสู่ระบบ ผู้ใช้ยังกรอก "ชื่อผู้ใช้งาน + รหัสผ่าน" เหมือนเดิม
(ภายในระบบจะแปลงชื่อผู้ใช้เป็นอีเมลสมมติ `ชื่อผู้ใช้@sts.local` — ไม่มีการส่งอีเมลจริง)

- สมัครสมาชิกแล้ว **ยังเข้าใช้งานไม่ได้** จนกว่าผู้ดูแลระบบ (Admin) จะกดอนุมัติ
- ข้อมูลสินค้า / รายการรับ-จ่าย อ่าน-เขียนได้เฉพาะผู้ใช้ที่ได้รับอนุมัติแล้วเท่านั้น
  (บังคับที่ฐานข้อมูลด้วย Row Level Security — การมี anon key อย่างเดียวเข้าถึงข้อมูลไม่ได้แล้ว)
- ไม่มีรหัสผ่านฝังในโค้ด และไม่เก็บรายชื่อผู้ใช้ไว้ใน localStorage ของเบราว์เซอร์อีกต่อไป

### ขั้นตอนตั้งค่าใน Supabase Dashboard (ทำครั้งเดียว ตามลำดับ)

1. **รัน SQL**
   ไปที่ Supabase Dashboard → **SQL Editor** → New query
   - ถ้าเป็นโปรเจกต์ใหม่ ให้รัน `supabase/schema.sql` ก่อน
   - จากนั้นคัดลอกเนื้อหาไฟล์ `supabase/migrations/002_auth_approval.sql` ทั้งหมด วางแล้วกด **Run**
     (รันซ้ำได้ ไม่เสียหาย)

2. **ปิดการยืนยันอีเมล**
   ไปที่ **Authentication → Providers → Email** แล้ว **ปิด "Confirm email"** → Save
   (อีเมล `@sts.local` เป็นอีเมลสมมติ รับอีเมลยืนยันไม่ได้ ถ้าไม่ปิดจะไม่มีใครเข้าระบบได้)

3. **ตั้งผู้ดูแลระบบ (Admin) คนแรก**
   - เปิดหน้าเว็บ → แท็บ **สมัครสมาชิก** → สมัครด้วยชื่อผู้ใช้ของแอดมิน
     (ระบบจะขึ้นว่า "สมัครสำเร็จ รอผู้ดูแลระบบอนุมัติ")
   - กลับไปที่ **SQL Editor** แล้วรัน (เปลี่ยน `ชื่อผู้ใช้แอดมิน` เป็นชื่อที่เพิ่งสมัคร):

     ```sql
     UPDATE public.profiles
     SET role = 'Admin', status = 'approved'
     WHERE username = 'ชื่อผู้ใช้แอดมิน';
     ```

   - เข้าสู่ระบบด้วยบัญชีนั้นได้เลย

4. **ผู้ใช้เดิมทุกคนต้องสมัครใหม่**
   บัญชีในระบบเก่าถูกเก็บไว้ในเบราว์เซอร์แต่ละเครื่อง (localStorage) จึงย้ายมาไม่ได้
   ให้ผู้ใช้เดิมทุกคนกด **สมัครสมาชิก** ใหม่ แล้วแอดมินเข้าไปที่
   **ตั้งค่า (ไอคอนเฟือง) → ผู้ใช้งาน → รออนุมัติ** แล้วกด **อนุมัติ**
   (ไอคอนตั้งค่าจะมีตัวเลขสีแดงแสดงจำนวนคนที่รออนุมัติ)

### การจัดการผู้ใช้ (แอดมิน)

ตั้งค่า → แท็บ **ผู้ใช้งาน**

- **รออนุมัติ**: รายชื่อคนที่สมัครเข้ามาใหม่ พร้อมวันที่สมัคร — กด **อนุมัติ** หรือ **ปฏิเสธ**
- **รายชื่อผู้ใช้งาน**: เปลี่ยนสิทธิ์ Admin/User, ระงับการใช้งาน หรืออนุมัติคนที่เคยถูกปฏิเสธอีกครั้ง
- ระบบต้องมี Admin ที่อนุมัติแล้วอย่างน้อย 1 คนเสมอ (บังคับทั้งในหน้าเว็บและในฐานข้อมูล)
- ไม่มีปุ่ม "เพิ่มผู้ใช้งาน" แล้ว เพราะการสร้างบัญชีแทนผู้อื่นต้องใช้ service role key
  ซึ่งห้ามใส่ในหน้าเว็บ — ให้ผู้ใช้สมัครเองแล้วแอดมินกดอนุมัติแทน
- ลืมรหัสผ่าน: แอดมินรีเซ็ตได้ที่ Supabase Dashboard → Authentication → Users
  (ค้นหา `ชื่อผู้ใช้@sts.local`)

## Deploy (Vercel)

ตั้งค่า Environment Variables `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY`
ใน Project Settings แล้ว redeploy (ดูรายละเอียดใน `.env.example`)
